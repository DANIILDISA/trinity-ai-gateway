## 1. Design Principles

### 1.1 Money is always BIGINT micro-rubles
Every monetary column stores **micro-rubles** (μ₽): `1 RUB = 1 000 000 μ₽`, as `BIGINT`. The same integer scale is reused for **micro-USD** (`1 USD = 1 000 000 μUSD`) in cost-tracking columns. No `NUMERIC`, `DECIMAL`, or `FLOAT` in the financial path. See [§9](#9-currency--precision-rules).

### 1.2 UUID primary keys
Every table uses `UUID` primary keys generated by `gen_random_uuid()`, except `system_settings`, which is keyed by a `VARCHAR(128)` `key`.

### 1.3 Append-only financial ledger
`transactions` is append-only: application code only ever `INSERT`s. The denormalized `users.balance_micro_rub` must always equal `SUM(transactions.amount_micro_rub)` for that user. The daily reconciliation task verifies this (see BILLING_LOGIC.md §11).

### 1.4 Soft deletes for user content
`conversations` carries a `deleted_at TIMESTAMPTZ` soft-delete (used for archive/restore). A daily purge hard-deletes rows soft-deleted > 30 days ago, cascading to `messages`.

### 1.5 Timestamps are UTC
All `TIMESTAMPTZ` columns store UTC (`server_default now()` where defaulted). The application converts for display.

### 1.6 Enums created explicitly
Six PostgreSQL `ENUM` types are created by migration `001`. ORM models reference them with `create_type=False` so the ORM never tries to re-create them.

**Cross-entity correlation key:** a single `request_id` (UUID, generated per chat request) links a `reservations` row, its eventual `transactions` debit (`idempotency_key = request_id`), the `usage_logs` row, and the assistant `messages` row.

| Child | Parent | `ON DELETE` |
|---|---|---|
| `refresh_tokens.user_id` | `users` | `CASCADE` |
| `password_reset_tokens.user_id` | `users` | `CASCADE` |
| `messages.conversation_id` | `conversations` | `CASCADE` |
| `usage_logs.conversation_id` | `conversations` | `SET NULL` |
| `chat_images.user_id` | `users` | `CASCADE` |
| `chat_images.conversation_id` | `conversations` | `SET NULL` |
| `chat_images.message_id` | `messages` | `SET NULL` |
| `transactions.user_id` / `.admin_user_id` | `users` | default `RESTRICT` (ledger never auto-deletes) |
| `reservations.user_id`, `usage_logs.user_id`, `conversations.user_id`, `notifications.user_id` | `users` | default `RESTRICT` |
| `usage_logs.api_key_id` | `api_keys` | default `RESTRICT` |
| `alerts.acknowledged_by` / `.resolved_by`, `admin_audit_log.actor_id`, `system_settings.updated_by` | `users` | default `RESTRICT`, nullable |

## 3. Migration History

Migrations are sequential, hand-written (no `--autogenerate`), each with `upgrade()` and `downgrade()`. Run with `docker compose exec backend alembic upgrade head`. Alembic connects via `DATABASE_URL_DIRECT` (bypassing PgBouncer) when set — see `alembic/env.py`.

| Rev | File | What it does |
|---|---|---|
| `001` | `001_initial_schema.py` | Creates 6 enums, 14 tables, all indexes, seeds `system_settings`. |
| `002` | `002_seed_model_pricing.py` | Seeds 4 launch models into `model_pricing` (at 85 RUB/USD, 1.15 markup). |
| `003` | `003_reservation_allow_zero.py` | Relaxes `reservations` CHECK from `reserved_micro_rub > 0` to `>= 0` (free models reserve 0). |
| `004` | `004_usage_log_tracking_fields.py` | Adds `usage_logs.prompt_length_chars`, `usage_logs.completed_at`. |
| `005` | `005_model_sync_fields.py` | Widens `model_pricing` status CHECK to include `'unavailable'`. |
| `006` | `006_model_stream_timeout.py` | Adds `model_pricing.stream_timeout_seconds` (default 30). |
| `007` | `007_api_key_accounts.py` | Adds `api_keys.account_name`, `api_keys.account_blocked`. |
| `008` | `008_model_capabilities.py` | Adds 5 capability flags to `model_pricing`. |
| `009` | `009_usage_log_web_search.py` | Adds `usage_logs.web_search_enabled`. |
| `010` | `010_chat_images.py` | Creates the `chat_images` table (15th table) + 3 indexes. |

## 4. Table Definitions

Column types below reflect the **current** schema after all 10 migrations.

### 4.1 `users`
Core account + denormalized balance. The available balance is always `balance_micro_rub − reserved_micro_rub`.

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` PK | `gen_random_uuid()` |
| `email` | `VARCHAR(255)` NOT NULL | as entered |
| `email_lower` | `VARCHAR(255)` NOT NULL | `GENERATED ALWAYS AS (lower(email)) STORED`; all lookups use this |
| `display_name` | `VARCHAR(100)` NOT NULL | |
| `password_hash` | `VARCHAR(255)` NULL | bcrypt; NULL for OAuth-only accounts (see §10) |
| `yandex_id` | `VARCHAR(64)` NULL | OAuth link slot — **never populated by current code** (see §10) |
| `role` | `VARCHAR(20)` NOT NULL `'user'` | CHECK `IN ('user','admin')` |
| `status` | `VARCHAR(20)` NOT NULL `'active'` | CHECK `IN ('active','blocked')` |
| `block_reason` | `TEXT` NULL | set when blocked |
| `balance_micro_rub` | `BIGINT` NOT NULL `0` | CHECK `>= 0` |
| `reserved_micro_rub` | `BIGINT` NOT NULL `0` | CHECK `>= 0` |
| `created_at` | `TIMESTAMPTZ` NOT NULL `now()` | |
| `updated_at` | `TIMESTAMPTZ` NOT NULL `now()` | bumped by app code, not a trigger |

**Constraints:** `uq_users_email_lower (email_lower)`, `uq_users_yandex_id (yandex_id)`, `chk_users_role`, `chk_users_status`, `chk_users_balance_nonneg`, `chk_users_reserved_nonneg`, `chk_available_balance (balance_micro_rub >= reserved_micro_rub)`.

### 4.4 `transactions`
The financial ledger. **Append-only.** Every balance change is one row.

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` PK | |
| `user_id` | `UUID` NOT NULL → `users` | no cascade (ledger survives) |
| `type` | `transaction_type` enum NOT NULL | `credit` \| `debit` \| `refund` \| `adjustment` |
| `amount_micro_rub` | `BIGINT` NOT NULL | sign by type (see CHECKs) |
| `balance_after_micro_rub` | `BIGINT` NOT NULL | balance snapshot after this row |
| `description` | `TEXT` NOT NULL | shown to user |
| `request_id` | `UUID` NULL | links debits to `usage_logs`/`messages` |
| `payment_id` | `VARCHAR(128)` NULL | YooKassa payment id for credits |
| `admin_user_id` | `UUID` NULL → `users` | who performed an `adjustment` |
| `admin_reason` | `TEXT` NULL | required for `adjustment` |
| `idempotency_key` | `VARCHAR(128)` NULL UNIQUE | dedup key (see below) |
| `created_at` | `TIMESTAMPTZ` NOT NULL `now()` | |

**`idempotency_key` conventions (from code):** credits use the YooKassa `payment_id`; debits use `str(reservation.request_id)`; adjustments use `adj:{uuid4}`.

**Constraints:** `uq_transactions_idempotency (idempotency_key)`, `chk_credit_positive`, `chk_debit_negative`, `chk_refund_positive`, `chk_adjustment_has_reason (type != 'adjustment' OR admin_reason IS NOT NULL)`.

> **Note:** `type = 'refund'` is a valid enum value with a CHECK, but **no application code path ever inserts a refund row** (see [§10](#10-known-inconsistencies) and BILLING_LOGIC.md §10). Failed requests release the reservation lock without creating a transaction.

## 8. Data Retention

The cleanup cron (`app/tasks/cleanup.py`) runs two jobs (see SPEC.md §11):

**Every minute — `release_expired_reservations`:** `reservations` still `active` after **5 minutes** → set `expired`, refund `users.reserved_micro_rub`, file a warning alert.

**Daily 04:00 UTC — `run_data_retention`:**

| Table | Rule |
|---|---|
| `refresh_tokens` | delete `expires_at < now()` |
| `password_reset_tokens` | delete `created_at < now() − 24h` |
| `notifications` | delete `created_at < now() − 90d` |
| `alerts` | delete `created_at < now() − 365d` |
| `conversations` | delete soft-deleted rows `deleted_at < now() − 30d` (CASCADE → `messages`) |
| `usage_logs` | delete `created_at < now() − 365d` |
| `admin_audit_log` | delete `created_at < now() − 3y` |
| `reservations` | delete `finalized/released/expired` with `finalized_at < now() − 90d` |

`transactions`, `model_pricing`, `api_keys`, `system_settings`, `users`, `chat_images` are **never** purged by this job.

## 9. Currency & Precision Rules

All conversions live in `app/core/constants.py`. `MICRO_PER_UNIT = 1_000_000`.

| Function | Behaviour |
|---|---|
| `rubles_to_micro(r)` | `r × 10⁶` |
| `kopeks_to_micro(k)` | `k × 10_000` (1 kopek = 10 000 μ₽) |
| `micro_to_display_balance(m)` | floor to 2 dp → `"847.53"` |
| `micro_to_api_string(m)` | signed, 4 dp → `"-0.3600"` |
| `usd_float_to_micro_usd(f)` | `round(f × 10⁶)` — the **only** float entry point |
| `micro_usd_to_micro_rub(mu, rate)` | `ceil(mu × rate / 10⁶)` |
| `calculate_token_cost_micro_rub(tokens, price_per_M_μ₽)` | `ceil(tokens × price / 10⁶)` |

**Rounding is always in the operator's favour:** costs `ceil()` (user pays slightly more), balance display floors (user sees slightly less). Markup math uses `round(markup × 100)` (not `int()`) so `1.25` → `125`, never `124`.

**Invariants enforced at the DB level:** `balance_micro_rub >= 0`, `balance_micro_rub >= reserved_micro_rub`, unique `idempotency_key` on `transactions`. `BIGINT` tops out at ~9.2 × 10¹⁸ μ₽ (≈ 9.2 trillion RUB).

## 10. Known Inconsistencies

Surfaced during this audit; documented here so they aren't mistaken for bugs in the schema description:

1. **`yandex_id` is dead.** The column, its unique constraint, and `password_hash` nullability all exist to support Yandex OAuth, but no backend code populates `yandex_id` — OAuth is not implemented (see SPEC.md §6).
2. **`transactions.type = 'refund'` and `usage_logs.status = 'refunded'` are never written.** Failed requests release the reservation lock; no refund transaction is created (see BILLING_LOGIC.md §10).
3. **`usage_logs.api_key_id`, `admin_audit_log.user_agent`, and `notifications.email_sent`/`email_sent_at`** are present in the schema but not populated by current code paths.
4. **Seed mismatch:** migration 002 prices the 4 launch models at 85 RUB/USD ×1.15, while the `system_settings` seed (001) sets the live rate to 82.50 ×1.25. They reconcile on the first tariff update or model sync — fresh installs briefly carry inconsistent stored RUB prices.
5. **`reconciliation_threshold_percent` is seeded but unused** — the reconciliation task uses hardcoded margin thresholds (0% / 10% / 20%).
6. **`estimation_buffer` is read by the estimator (default 1.3) but is not in the seed** — it only exists if an admin or migration adds it later.
